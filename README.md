## 启动

### 最简单的方式：电脑上的 Android 模拟器

1. 在 Windows 开始菜单打开 PowerShell，依次输入：

   ```powershell
   cd E:\AndroidProject\AppDemo\server
   python run.py
   ```

   看见 `NutriPulse listening on http://127.0.0.1:8787` 后保持该窗口打开。第一次启动会自动建立本地数据库。可用电脑浏览器打开 `http://127.0.0.1:8787/api/v1/health` 验证服务；返回 `status: ok` 即正常。
2. 打开 Android Studio，选择 **File → Open**，打开 `E:\AndroidProject\AppDemo`（项目根目录，不是 `server` 或 `client`）。等待 Gradle 同步结束，在顶部选择一个 Android 模拟器和 `app`，点击绿色 ▶ 运行。正常情况下 App 会自动连接电脑服务，无需输入配对码。
3. 若 App 提示连接失败，先确认 PowerShell 窗口仍在运行；此机器先前的模拟器曾需要执行 `E:\AndroidSDK\platform-tools\adb.exe reverse tcp:8787 tcp:8787`，然后在 App 的“我的 → 本地电脑连接”把地址改为 `http://127.0.0.1:8787` 并保存。模拟器重启后可能需重新执行端口转发。

拍照识餐与 AI 对话另外需要配置联网 Agent 网关；未配置时仍可使用手工记餐、训练、规则推荐和本地统计。真机连接需要局域网地址与配对，步骤见下文；第一次体验建议先用模拟器。

### 开发与真机配置

1. 在 `server/` 先运行 `python -m pip install -r requirements.txt`，再运行 `python run.py`。默认监听 `127.0.0.1:8787`，SQLite 自动创建并迁移到 `server/data/nutripulse.sqlite3`，自动填充食品、场景菜品和六套官方训练计划。
2. 用 Android Studio 打开本目录并运行 `app` 模块（最低 Android 8 / API 26）。Android 模拟器默认通过 `http://10.0.2.2:8787` 连接主机服务。真机需在“我的 → 本地电脑连接”填写电脑局域网地址。
3. 真机局域网模式启动前设置 `NUTRIPULSE_HOST` 为电脑的明确私有网卡地址（不可用 `0.0.0.0`），并在电脑端设置至少 24 字符的随机 `NUTRIPULSE_API_TOKEN` 作为管理员密钥。服务启动时在电脑终端显示有效 10 分钟的一次性配对码；在手机“我的 → 本地电脑连接”填写电脑地址和配对码，客户端把限时访问凭据保存在 Android Keystore 保护的本机存储中，无需把管理员密钥复制到手机。HTTP 明文连接只应在可信私有网络使用，不应对公网开放；网络不可信时需配置 HTTPS。

若当前模拟器环境无法连接默认 `10.0.2.2:8787`，可执行 `adb reverse tcp:8787 tcp:8787`，再在“我的 → 本地电脑连接”将地址设为 `http://127.0.0.1:8787`。模拟器重启后需重新执行端口转发；本轮 QA 已撤销测试转发。

`python -m unittest discover -s tests -v` 可在 `server/` 运行服务端测试；Windows 下在项目根目录执行 `gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest` 构建客户端与测试 APK。若本机因 Gradle 守护进程连接失败而无法构建，可在 PowerShell 先设置 `$env:TEMP='E:\AndroidProject\AppDemo\tmp'`、`$env:TMP=$env:TEMP`、`$env:JAVA_OPTS='-Xms64m -Xmx2048m -Dfile.encoding=UTF-8 -Djava.io.tmpdir=E:\AndroidProject\AppDemo\tmp'` 与 `$env:GRADLE_OPTS='-Dorg.gradle.daemon=false'`，再附加 `--no-daemon` 重试；依赖已缓存时可加 `--offline`。临时目录须预先存在并按实际项目路径调整。详见 [server/README.md](server/README.md)。

## 已实现的闭环

- 个人档案、体重/体脂、BMR/TDEE、阶段目标试算与确认、目标计算输入快照、饮食/训练偏好；四餐记账、食品库检索、最近常用食物、g/ml/份/个份量与可选克数换算、饮水和只读步数卡、拍照识餐后人工核对、计划转实际摄入。手工营养素可留空，服务端保留逐项“已知/未知”标记，日报和周期统计提示不完整，不再把未填项当作确认的零；旧记录保守标为未知。客户端待上传照片一律按方向信息旋转、缩放并重新编码为 JPEG；服务端还会核验真实图片格式、完整解码和像素上限，再以无 EXIF 的 JPEG 交给 Agent，避免原图中的 GPS 等元数据外传。识餐失败时可经用户确认将归一化照片加密暂存本机，稍后重试或删除。
- 有氧/MET 或自填热量记账；快速录入可选择项目、强度和时长，保存前按当前体重预估消耗，记录中保留估算来源与算法版本。健身看板展示每日活动目标、训练分钟、力量估算和设备来源/同步时间。力量组数/重量与 90 秒休息计时、六套官方计划报名与日程跟练；可按个人训练水平及当前目标筛选浏览计划，仍能切回全部计划。今日计划可按组或时长记录，个人动作替换需填写原因，提前结束会标为部分完成，容量及完整完成数分别结算。Health Connect 授权后同步最近 7 天设备数据；活动热量改为按时间窗分批同步，能判定的设备—手工重叠进入冲突队列，由用户选择处置，旧日汇总数据明确保守回退。健身页打开期间约每分钟刷新，并做样本去重与体重/体脂目标校准。个人页可查看连接、样本数和同步时间，并选择撤销连接且保留原始历史，或永久删除该连接的样本及其派生测量/目标；Health Connect 撤销时也会尝试撤回本应用的系统健康权限。
- 六套官方计划的 v2 目录补全了适用人群、风险提示、热身冷身、替代动作、进阶规则和完成标准；高阶力量计划按积累、强化、减量、技术测试分周。升级只改官方目录，新旧报名的训练实例仍保留当时报名的模板快照。
- 健身页支持独立的按秒计时动作；计划内“平板支撑 20 秒”等动作会自动生成秒数字段，保存到既有训练组时长列，不能与次数混填，也不会产生虚假的 kg 容量。
- 自重训练的组重量可留空，次数与完成状态仍会入账；外部负重容量只统计实际填写重量的已完成组，不把体重假定成器械重量。恢复回归计划可据此完成自重跟练。
- 按目标、餐次、场景、营养预算、估算单餐费用、最长自煮时间及过敏/忌口筛选菜品，口味参与排序；可选 Agent 重排和多轮对话，确认后写入饮食计划。用户可反馈不喜欢、重复或不合适以调整后续排序，不会自动变成永久忌口；盲盒转盘只从通过硬约束的候选池抽一份，支持换一个及一键预记。对话方案展示食材、热量、可得的宏量、可能过敏原及可核算的价格；设置价格上限后，只允许引用服务端已登记的安全菜谱，模型不能虚构价格或食材。切换份量时即时缩放菜谱食材、营养和估算价格，并提示超出热量/价格上限；服务端确认时再按最新日账本校验。未知价格明确标为未知，Demo 价格是静态估算，不是实时报价。
- 日/周/月/年能量统计（含 BMR/TDEE 基准、总消耗和净差）、宏量营养供能结构、饮水/已知纤维/三餐记账/计划跟练概览、体脂—训练容量双轴趋势及独立的体重趋势、规则/Agent 营养摘要、经敏感信息确认后的 PDF 导出；RSS 资讯卡片。习惯概览不把漏记当作零，也不把未结束的今天计为训练失败；PDF 按所选周期在服务端内存生成，需要安装 `server/requirements.txt` 中的 ReportLab。
- 个人页可分类导出可读 JSON，并在预览影响、输入确认短语后清空饮食、运动设备、AI 或身体档案数据；全部清空会重置本地档案及客户端连接令牌。
- 本地服务在运行中执行 SQLite 一致快照，自动保留 7 份日备份及 4 份周备份；迁移前备份、手工校验和恢复到新数据库路径的工具见 [服务端操作说明](server/README.md)。备份目前未加密，需自行保护目录访问权限。
- 个人页可导出最近 500 条脱敏连接诊断：仅记录请求模块、状态、耗时及错误类型，不保存健康正文、网址参数或令牌；重启电脑服务即清空。
- 局域网配对码仅能成功使用一次，错误尝试 5 次后锁定；配对令牌最长有效 24 小时且服务重启即失效。电脑端管理员可使用 `POST /api/v1/auth/pair-code` 和管理员密钥生成新码。旧版手工令牌入口仍保留作兼容，不再回显已保存凭据。

## 当前边界

- Agent 需用户自行提供联网网关；未配置时拍照识餐和对话不可用，菜品推荐与营养分析显示规则降级来源。
- Android Health Connect 已接入，但依赖设备上安装/启用 Health Connect 及其他设备应用先把数据写入其中；它不是对手表传感器的毫秒级直播流。Apple Health 需要 iOS 端或中介桥接，本 Android Demo 无法直接连接 Apple Watch。
- 当前单人档案时区固定为 `Asia/Shanghai`。饮食、推荐、健身、数据、导出文件名与 Health Connect 分日统一通过客户端 `UserCalendar` 使用该自然日；推荐页跨午夜会先刷新预算再允许生成。尚未提供修改个人时区的交互与迁移。
- 已完成此前单一模拟器的基本视觉与关键闭环验收；新增的 Health Connect 区间同步与冲突处置已通过构建和服务端黑盒/集成测试，但尚无真实穿戴设备或 Health Connect 记录的端到端验收。也尚无真机、多尺寸、完整弱网/无障碍测试及生产级安全审计。食品及消耗值为估算，不是医疗建议。
